Architecture

What the gateway actually does.

The agent never talks to the protected API directly. Mandate evaluates the grant, then a trusted connector is the only path upstream.

  1. 01Principalsigned grant
  2. 02Agentintent only
  3. 03Mandatepolicy · budget · route
  4. 04Humanif required
  5. 05Upstreamregistered route
  6. 06Receiptsigned result

No valid authorization → no upstream execution.

Control plane

A state machine, not a suggestion.

Every intent is checked against a signed grant, a server-side route registry, and an atomic ledger. Outcomes are explicit: authorized, denied, human-required, executed, failed, or unknown.

  1. 01PrincipalIssues a signed grant with scope, time, and budget.
  2. 02Agent intentNames an action. Cannot supply a URL, host, or network policy.
  3. 03MandateVerifies identity, grant, audience, nonce, budget, and destination.
  4. 04Human step-upIf required, approval revalidates the grant. It is not a shortcut.
  5. 05Registered routeOnly the trusted connector may call the upstream. Redirects are not followed.
  6. 06Signed receiptThe result is recorded, including EXECUTION_UNKNOWN when the remote side is unclear.

Core guarantees

A narrow boundary with explicit invariants.

Cryptographic grants

Principal authorization is signed and independently verifiable. Agent claims are not authority.

Atomic budget accounting

Reserve, commit, and release live in the ledger. v0.2.1 binds spend to the authorization day.

Human approval that revalidates

Step-up does not skip evaluation. The grant is checked again before execution.

Server-side destinations

Routes come from a trusted registry. Public is the default. Private requires server-side opt-in.

Uncertainty stays explicit

A timeout becomes EXECUTION_UNKNOWN. The reservation is kept instead of guessed away.

Signed execution receipts

Outcomes are enforcer-signed objects for audit, not log lines that can drift.

Developer surface

Small on purpose.

The gateway exposes only what is required to submit intent, attach constrained approval, inspect receipts, and check health.

  • POST /v1/intentsSubmit a signed agent intent for evaluation.
  • POST /v1/approvalsAttach human approval where policy requires it.
  • GET /v1/receipts/{id}Read the signed authorization and execution receipt.
  • GET /healthGateway health and enforcer identity.

Deliberate scope

Not an identity stack. Not a payment network.

Keeping the product narrow makes the security properties testable. Mandate is an enforcement gateway for AI-agent grants — nothing more is claimed in v0.2.1.

In v0.2.1

  • Signed grants and constraints
  • Nonce consumption
  • Daily budgets with day binding
  • Human approval with revalidation
  • Server-side route policy
  • Explicit execution states
  • Signed receipts and audit records

Not in v0.2.1

  • MCP or A2A adapters
  • EUDI / wallets
  • Subdelegation
  • Organization credentials
  • Marketplace flows
  • Payment-network behavior
  • A general-purpose UI

Next step

Give agents less implicit power.

Make authority explicit, bounded, auditable, and verifiable before a protected action crosses the network boundary.

Authorization
before execution.

A permission layer for AI agents. Your agent proposes a call — Mandate lets it through only if a signed grant allows it: in scope, under budget, a vendor on the list, a human’s approval above a threshold. Every decision becomes a receipt nobody can quietly edit.

Architecture

Six stages.
One enforcement boundary.

The request moves through these stages in order. Human approval is conditional. If any required stage fails, the upstream connector is never reached.

  1. 01Principalsigned grant
  2. 02Agentintent only
  3. 03Mandatepolicy · budget · route
  4. 04Humanif required
  5. 05Upstreamregistered route
  6. 06Receiptsigned · chained

No valid authorization → no upstream execution.

Control plane

A state machine,
not a suggestion.

Every intent is checked against a signed grant, a server-side route registry, and an atomic ledger. The states a receipt passes through are verifiable afterwards, not just its final one.

  1. 01PrincipalIssues a signed grant with scope, time, and budget.
  2. 02Agent intentNames an action. Cannot supply a URL or network policy.
  3. 03MandateVerifies identity, grant, audience, nonce, budget, and destination.
  4. 04Human step-upIf required, approval revalidates the grant.
  5. 05Registered routeOnly the trusted connector may call upstream.
  6. 06Signed receiptThe result is recorded and chained, including EXECUTION_UNKNOWN.

Receipt chain · v0.7.0 – v0.9.0

History you cannot
edit quietly.

A signed receipt proves who wrote it. It proves nothing about the set of receipts — an operator with database access could delete a row and every remaining signature still verified. Each state a receipt reaches now appends an enforcer-signed entry that commits to the one before it.

the operator cuts the tail off the chain
$ mandate chain verify --db ledger.sqlite
tenant default: 9 entries intact
$ echo $?  → 0

$ mandate chain verify --anchors anchors.jsonl
TAMPERED — an anchor recorded seq 12
for this tenant, and the chain no
longer reaches it
$ echo $?  → 1
Anchors, sent to a witnessv0.9.0

A prefix of a valid chain is a valid chain, so truncation is invisible from inside a database. The gateway posts its heads to a witness someone else runs, on a schedule; --anchors checks them. A witness that does not accept is a failure, never a silence.

Key rotationv0.8.0

The rotation entry is signed by the key being replaced, so a retired key cannot appoint anyone and nothing before a rotation can be re-signed by the key after it.

Legal roadsv0.8.0

The states a receipt passed through are checked against the state machine, not only its destination.

Verification needs no keyv0.7.0

The person who most needs to check a chain is the one who does not trust whoever runs it.

A compromised signing keyBounded, not closed

It re-signs receipts and chain together while it is held. Rotation bounds the window; nothing bounds what the key does inside it.

Core guarantees

A narrow boundary
with explicit invariants.

Cryptographic grants

Principal authorization is signed and independently verifiable.

Atomic budget accounting

Spend is kept in integer minor units, bound to the authorization day.

Human approval that revalidates

Step-up does not skip evaluation. Over MCP it is one command, and the agent's key cannot give it.

Server-side destinations

Public is the default. Private requires server-side opt-in.

Uncertainty stays explicit

A timeout becomes EXECUTION_UNKNOWN rather than a guess.

Keys that never enter the process

AWS KMS, GCP Cloud KMS and Vault sign without handing the key back.

Authenticated and tenant-scoped

Every call carries an API key. A tenant never sees another tenant's records.

In front of MCP tools

The guard re-exposes an MCP server's tools and authorizes every call. Claude Code and Cursor connect with one line.

A few milliseconds a decision

Measured, with the method and the ceiling written down, not hidden.

One file, read strictly

Routes, signers, limits and anchoring come from one configuration. A misspelt key is an error, never a default.

Unknown outcomes, settled on the record

An operator who asked the upstream resolves EXECUTION_UNKNOWN. Who decided and why is signed into the receipt.

Hardening status

Proven as behavior,
not as copy.

289 gates, written as the attacks rather than as the features, passing on Python 3.11, 3.12 and 3.13 from a clean clone.

Policy held at the socketClosed

HTTPS connects to the address the destination policy checked, and no environment proxy re-resolves it. G202, G204.

One limit across workersClosed

The rate limit lives in the ledger, so four workers do not mean four times the limit. G207.

Nothing sent that cannot be recordedClosed

An execution whose receipt could outgrow the signer is refused before dispatch. G226.

No vendor, no paymentClosed

An allow-list was consulted only when a call named a vendor, so naming none walked past it. A payment now has to name who is paid. G251, G252.

Approvals expireClosed

An approval without a timestamp counted as fresh forever. It now carries one and lives ten minutes. G249, G250.

Typos are errorsClosed

A misspelt limit used to be dropped and the grant issued without it. G217.

What the upstream receivedKnown limit

The receipt binds the bytes the gateway sent. Only the upstream can say what arrived.

Developer surface

Small
on purpose.

  • POST /v1/intentsSubmit a signed agent intent.
  • POST /v1/approvalsAttach human approval when required.
  • GET /v1/receipts/{id}Read the signed receipt.
  • GET /v1/infoChain head for the caller's tenant.
  • GET /healthLiveness only. Reveals nothing.
  • mandate gateway serveRun it from one configuration file.
  • mandate gateway resolveSettle an unknown outcome, on the record.
  • mandate mcp approveApprove a held MCP call. It runs once.
  • mandate demo shopWatch an agent shop against a grant.

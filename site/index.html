Authorization before execution.

Mandate is an enforcement gateway for AI agents. It converts principal intent into scoped, auditable, budget-aware authority before a protected upstream call is allowed to happen.

The control plane

Agents can propose. Mandate decides what may execute.

A principal issues a cryptographically signed grant. Every agent intent is checked against scope, audience, time, amount, daily budget, approval requirements, nonce state, and the server-side route registry.

Core guarantees

A narrow enforcement boundary with explicit invariants.

01

Cryptographic grants

Principal authorization is signed and independently verifiable. Agent-provided claims do not become authority by themselves.

02

Atomic budget accounting

Reservation and commit/release operations live in the SQLite transaction layer. v0.2.1 binds spend to the authorization day.

03

Human approval that revalidates

Approval is not an execution shortcut. The grant is re-evaluated and the state machine preserves the authorization boundary.

04

Server-side destinations

Agents cannot supply target URLs or override network policy. Routes come from a trusted registry and redirects are not followed.

05

Execution uncertainty is explicit

A timeout becomes EXECUTION_UNKNOWN. Mandate keeps the reservation instead of pretending the remote side definitely failed.

06

Signed execution receipts

Outcomes are recorded as enforcer-signed receipts, giving downstream systems a durable object for audit and verification.

API surface

Small by design.

The gateway exposes only the minimum surfaces required to submit intent, approve constrained actions, inspect receipts, and check health.

  • POST /v1/intentsSubmit a signed agent intent for evaluation.
  • POST /v1/approvalsAttach human approval where policy requires it.
  • GET /v1/receipts/{id}Read the signed authorization / execution receipt.
  • GET /healthGateway health and enforcer identity.

Deliberate scope

Mandate is not trying to be everything.

The current release is an enforcement gateway, not an identity ecosystem or payment network. Keeping that boundary narrow makes its security properties easier to reason about and test.

Included now

Grants, constraints, nonce consumption, daily budgets, human approval, route policy, execution state, signed receipts, audit records.

Not in v0.2.1

MCP, A2A, EUDI, wallets, subdelegation, organization credentials, marketplace flows, payment-network behavior, or a general UI.

Failure-aware

Mandate does not claim perfect exactly-once HTTP. When remote execution cannot be determined, the state is explicitly EXECUTION_UNKNOWN.

Give agents less implicit power.

Make authority explicit, bounded, auditable, and verifiable before protected actions cross the network boundary.

Authorization before execution.

Mandate sits in front of protected tools. An AI agent may propose an action. It does not execute until a signed, scoped, budget-aware grant has been verified.

Architecture

Six stages. One enforcement boundary.

The request moves through these stages in order. If any stage fails, the upstream connector is never reached.

  1. 01Principalsigned grant
  2. 02Agentintent only
  3. 03Mandatepolicy · budget · route
  4. 04Humanif required
  5. 05Upstreamregistered route
  6. 06Receiptsigned result

No valid authorization → no upstream execution.

Control plane

A state machine, not a suggestion.

Every intent is checked against a signed grant, a server-side route registry, and an atomic ledger.

  1. 01PrincipalIssues a signed grant with scope, time, and budget.
  2. 02Agent intentNames an action. Cannot supply a URL or network policy.
  3. 03MandateVerifies identity, grant, audience, nonce, budget, and destination.
  4. 04Human step-upIf required, approval revalidates the grant.
  5. 05Registered routeOnly the trusted connector may call upstream.
  6. 06Signed receiptThe result is recorded, including EXECUTION_UNKNOWN.

Core guarantees

A narrow boundary with explicit invariants.

Cryptographic grants

Principal authorization is signed and independently verifiable.

Atomic budget accounting

v0.2.1 binds spend to the authorization day.

Human approval that revalidates

Step-up does not skip evaluation.

Server-side destinations

Public is the default. Private requires server-side opt-in.

Uncertainty stays explicit

A timeout becomes EXECUTION_UNKNOWN.

Signed execution receipts

Outcomes are enforcer-signed objects for audit.

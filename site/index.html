Security invariant

If the grant is invalid,
the tool never runs.

Agents may propose. They do not choose destinations, invent authority, or skip the ledger. Mandate sits in front of the protected connector and evaluates identity, grant, policy, audience, nonce, budget, and human step-up before any request leaves the boundary.

Control plane

A state machine, not a suggestion.

Every intent is checked against a signed grant, a server-side route registry, and an atomic SQLite ledger. Outcomes are explicit: authorized, denied, human-required, executed, failed, or unknown.

  1. 01

    Principal defines authority

    A scoped, time-bound, budget-bound grant is issued. Agent claims are not authority by themselves.

  2. 02

    Agent submits intent

    The request names an action. It cannot supply a target URL, host, proxy, or network policy.

  3. 03

    Gateway evaluates

    Identity, grant, audience binding, nonce, budget reservation, destination policy, and optional human approval.

  4. 04

    Trusted connector fires

    Only a registered route is reachable. Redirects are not followed. A signed receipt records the result.

Core guarantees

Narrow boundary. Explicit invariants.

Cryptographic grants

Principal authorization is signed and independently verifiable. The agent cannot mint power by assertion.

Atomic budget accounting

Reserve, commit, and release live in the ledger. v0.2.1 binds spend to the authorization day, not the execution clock.

Human approval that revalidates

Step-up is not an execution shortcut. The grant is re-evaluated and the authorization boundary is preserved.

Server-side destinations

Routes come from a trusted registry. Public is the default. Private networks require explicit server-side opt-in.

Uncertainty stays explicit

A timeout becomes EXECUTION_UNKNOWN. The reservation is kept instead of pretending the remote side failed.

Signed execution receipts

Outcomes are enforcer-signed objects. Downstream systems get a durable record, not a log line that can drift.

Developer surface

Small on purpose.

The gateway exposes only what is required to submit intent, attach constrained approval, inspect receipts, and check health.

  • POST /v1/intentsSubmit a signed agent intent for evaluation.
  • POST /v1/approvalsAttach human approval where policy requires it.
  • GET /v1/receipts/{id}Read the signed authorization and execution receipt.
  • GET /healthGateway health and enforcer identity.

Deliberate scope

Not an identity stack. Not a payment network.

Keeping the product narrow makes the security properties testable. Mandate is an enforcement gateway for AI-agent grants — nothing more is claimed in v0.2.1.

In v0.2.1

  • Signed grants and constraints
  • Nonce consumption
  • Daily budgets with day binding
  • Human approval with revalidation
  • Server-side route policy
  • Explicit execution states
  • Signed receipts and audit records

Not in v0.2.1

  • MCP or A2A adapters
  • EUDI / wallets
  • Subdelegation
  • Organization credentials
  • Marketplace flows
  • Payment-network behavior
  • A general-purpose UI

Next step

Give agents less implicit power.

Make authority explicit, bounded, auditable, and verifiable before a protected action crosses the network boundary.
